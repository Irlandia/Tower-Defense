# Архітектура td.local

Цей документ — **контракт**: нові модулі й правки мають йому відповідати. Якщо архітектура змінюється — спершу оновлюється цей файл (і `docs/decisions.md`), потім код. Огляд знайдених проблем — `docs/code-review.md`.

## 1. Принципи
1. **Шари з односпрямованими залежностями** (вище знає про нижче, нижче — ніколи про вище). Циклічних імпортів немає.
2. **Симуляція чиста й детермінована**: без DOM, `Math.random`, `Date.now`; вхід — `(state, cmds)`, вихід — новий стан + `state.events`.
3. **Клієнт — тонка оболонка**: шле команди, малює стан, реагує на події. Правил гри там немає.
4. **Один спільний контекст** (`app`) + **шина подій** (`bus`) замість глобальних змінних і прямих викликів між UI-модулями.
5. **Дані окремо від коду**: баланс — у `src/sim/data.js`.
6. **Без збірки і npm**: чисті ES-модулі, JSDoc-типи в `src/sim/types.js`.
7. **Мережа не довіряє вхідним повідомленням**: усе з `net` проходить валідацію (`src/client/netplay.js`) і команди перевіряються в симуляції.

## 2. Шари і залежності

```
 index.html ─► src/main.js (bootstrap: імпорт модулів, реєстрація кадрових хуків, старт)
                    │
   ┌────────────────┴──────────────────────────────────────────────┐
   │ UI-шар            src/client/ui/*                             │
   │  hud, popup, menu, talents, endscreen, banner, input, tutorial│
   │  actions, feedback, overlay, icons, cursors, story, layout    │
   └───────────────┬───────────────────────────────────────────────┘
                   │ викликає / підписується на bus
   ┌───────────────┴───────────────────────────────────────────────┐
   │ Application-шар   src/client/*                                │
   │  app.js (контекст+bus) · session.js (життєвий цикл забігу)    │
   │  loop.js (фіксований крок) · roster.js · netplay.js (протокол)│
   └───────────────┬───────────────────────────────────────────────┘
                   │
   ┌───────────────┴──────────────┐   ┌────────────────────────────┐
   │ Інфраструктура               │   │ Рендер (лише читає стан)   │
   │  net.js (PeerJS-транспорт)   │   │  render.js, background.js,│
   │  api.js (HTTP-клієнт)        │   │  critters.js, say.js,      │
   │  meta.js (localStorage)      │   │  audio.js                  │
   │  audio.js                    │   └────────────────────────────┘
   └───────────────┬──────────────┘
                   │
   ┌───────────────┴───────────────────────────────────────────────┐
   │ Домен: src/sim/*  (чистий, детермінований)                    │
   │  data → rng → mapgen → queries → combat → waves → commands    │
   │  → sim.js (createGame, step, оновлення сутностей; фасад)      │
   └───────────────────────────────────────────────────────────────┘
```

Правило: `src/sim/*` не імпортує нічого поза `src/sim`. Рендер імпортує лише `sim`. `src/client/*` імпортує `sim`, `meta`, `net`, `api`, рендер. UI-модулі не імпортують один одного циклічно: спільні дії — через `actions.js`, `session.js` або `bus`.

## 3. Домен: `src/sim`
| Файл | Відповідальність |
|---|---|
| `data.js` | Увесь баланс і конфіг, `VERSION` |
| `rng.js` | seeded RNG (`rand`, `randInt`) у `state.rngState` |
| `mapgen.js` | Процедурна карта: лінії, ставки, ферма (`genClassic`, `genCircle`, `placeFarm`, `posAt`) |
| `queries.js` | Чисті запити до стану: `canPlace`, `towerAt`, `towerStats`, `placeCost`, … |
| `combat.js` | `damage`, `kill`, `ignite`, `explode`, `spawn`, `pickCards` |
| `waves.js` | `planLanes`, `startWave` (склад хвилі, боси) |
| `commands.js` | Реєстр обробників команд (патерн **Command**): `COMMANDS[type](s, pl, pi, c)` |
| `sim.js` | `createGame`, `step`, оновлення ворогів/веж/снарядів; **ре-експортує публічний API** (тести й клієнт імпортують лише з `sim.js`) |
| `types.js` | JSDoc-типи: `GameState`, `Command`, `GameEvent`, `Player` |

### Додати нову команду
1. Тип у `types.js` (`Command`).
2. Обробник у `commands.js` — **з валідацією** (цілі координати, власник, золото).
3. Клієнтська дія в `actions.js`/`input.js`, що викликає `session.send({...})`.
4. Тест у `tests/sim.html`, `VERSION++` у `data.js`.

### Події
Симуляція пише `state.events` (`{type, x, y, p?, ...}`); рендер перетворює на частинки, `feedback.js` — на звук і банери. Подія з полем `p` належить гравцеві `p`.

## 4. Application-шар: `src/client`
- **`app.js`** — єдиний об'єкт стану клієнта `app` (`state`, `running`, `paused`, `speed`, режим меню, нік, …), `ui` (вибір/наведення), `net`, `meta`, `sfx`, `music`, `renderer`, `bus`. Модулі читають/пишуть `app.*`; жодних модульних `let`, що ділиться між файлами.
- **`bus`** — `on(evt, fn)`, `emit(evt, ...args)`. Каталог подій:
  | Подія | Хто емітить | Навіщо |
  |---|---|---|
  | `run:start` | session | скинути UI, музику, банер, панель веж |
  | `run:resume` | session | закрити меню |
  | `run:end` `{won, earned, record}` | session | показати екран кінця |
  | `run:endless` | session | закрити екран кінця, банер |
  | `menu:show` | session | відкрити меню/лобі |
  | `net:status` `(text, kind)` | netplay | рядок статусу |
  | `roster:changed` | roster/netplay | перемалювати список гравців |
  | `sim:events` `(events, quiet)` | loop | звук/банери/реакції UI |
  | `frame` | loop | кадрові хуки UI (курсори, підписи, HUD) |
  | `banner` `(text, cls, sub, ms)` | будь-хто | показати банер |
- **`session.js`** — життєвий цикл: `startGame`, `newRun`, `resync`, `send(cmd)`, `finishRun`, `canResume/resumeGame`, `enterLobby`. Єдине місце, що створює `state` і веде `cmdLog`.
- **`loop.js`** — фіксований крок 20 Гц, інтерполяція, фоновий тікер у Worker, режими solo/host/guest.
- **`roster.js`** — склад кімнати (`app.roster`, `slotIdx`), `broadcastRoster`, `nickOf`.
- **`protocol.js`** — чиста валідація вхідних мережевих повідомлень (`validate`), без DOM.
- **`netplay.js`** — обробники повідомлень, heartbeat. Формат повідомлень — у `docs/net-protocol.md`.

## 5. UI-шар: `src/client/ui`
Кожен модуль: (а) реєструє DOM-слухачів при імпорті, (б) підписується на `bus`, (в) експортує лише те, що потрібно іншим. Перемальовування DOM — лише коли змінився «ключ» (`key !== lastKey`), щоб не плодити роботу щокадру.
- `actions.js` — дії гравця (вибір вежі, здібності, апгрейд, пауза…) — спільні для миші, клавіатури й попапу.
- `input.js` — миша/клавіатура → `actions`/`session.send`.
- `hud.js` — панель веж/здібностей, інфо-панель, лічильники.
- `popup.js` — меню вежі/перешкоди на карті.
- `menu.js` — лобі, режими, кампанія, дерево талантів, таблиця лідерів, нік, мережеві кнопки.
- `src/treeui.js` — екран дерева талантів (DOM, викликається з `menu.js`).
- `tutorial.js` — підказки першої соло-гри (localStorage `pixeltd-tutorial-done`), підсвічує клітинку через `ui.tutorTile`.
- `talents.js`, `endscreen.js`, `banner.js`, `feedback.js`, `overlay.js` (курсори партнерів), `icons.js`, `cursors.js`, `story.js`, `layout.js`.

## 6. Мережа (кооп)
Хост-авторитетний lockstep: хост збирає команди (`pending`), кожен тік розсилає `{t:'tick', cmds}`; гості програють ті самі тіки. Версія гри перевіряється при підключенні (`VERSION`). Деталі — `docs/net-protocol.md` і скіл `multiplayer-sync`.

## 7. Безпека
- Весь HTML з користувацьких рядків (ніки) — через `esc()`; `esc` екранує `& < > " '`.
- Код кімнати — `crypto.getRandomValues`.
- Повідомлення з мережі: тип/форма перевіряються у `netplay.js`; координати/ідентифікатори — цілі числа в діапазоні.
- Симуляція валідує команди незалежно від клієнта.
- API (`api/api.php`): таблиця лідерів — довіряє клієнту результат (обмежено кліпінгом і rate-limit); відомі ризики — у `docs/code-review.md`.

## 8. Тестування
- `tests/sim.html` — детермінізм, механіки, баланс-бот. `tests/render.html` — смоук рендеру. Обидва мають вивести `ALL PASSED`.
- `tests/client.html` — смоук клієнтських модулів (імпорти без помилок, шина, валідація повідомлень).
- CI (job `test` у `.github/workflows/deploy.yml`) запускає всі три в headless Chrome; деплой (`needs: test`) іде лише після зеленого прогону.

## 9. Угоди
- Коментарі — англійською поруч із кодом, документація й UI-тексти — українською (як зараз).
- Один модуль — одна відповідальність; файл > ~400 рядків — ознака, що треба ділити.
- Нові константи балансу — у `data.js`; нові команди — за чекслістом з п. 3.
- Зміна `src/sim` ⇒ `VERSION++`.
