# Мережевий протокол (кооп)

Транспорт: PeerJS/WebRTC, зірка — хост + до 3 гостей (`src/net.js`). Усі повідомлення — JSON-об'єкти з полем `t`. Валідація — `src/client/netplay.js` (`validate`); невідомі/некоректні повідомлення відкидаються.

## Хост → гості
| `t` | Поля | Призначення |
|---|---|---|
| `welcome` | `slot, v` | привітання, перевірка версії |
| `roster` | `list[{slot,nick,idx}]` | склад кімнати |
| `start` | `seed, opts, v, idx` | старт забігу |
| `resync` | `seed, opts, log, tick, v, idx` | повторна синхронізація (реконект/повернення з меню) |
| `tick` / `cmds` | `cmds[]` | крок симуляції / команди без кроку |
| `lobby` | — | хост вийшов у меню |
| `end` | `won` | кінець гри |
| `full`, `mismatch` | `v?` | відмова |
| `cursor` | `idx,x,y` | курсор іншого гравця |
| `ping` | — | heartbeat |

## Гість → хост
| `t` | Поля |
|---|---|
| `hello` | `nick, v, perks` |
| `cmd` | `cmd` (хост підставляє `p` за слотом) |
| `cursor` | `x,y` |
| `ping` | — |

## Інваріанти
- Лише хост веде годинник; гість не симулює самостійно.
- `p` у команді завжди виставляє хост, а не гість.
- Зміна `src/sim` ⇒ `VERSION++`, інакше гравці тихо розсинхронізуються.
- Нове повідомлення = рядок у цій таблиці + гілка в `validate` + тест у `tests/client.html`.
