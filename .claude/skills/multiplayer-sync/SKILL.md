# Мультиплеєр: правила

**Модель** (`src/net.js`, `src/main.js`): WebRTC peer-to-peer через PeerJS, кімната за 5-символьним кодом. Хост веде годинник 20 Гц і розсилає список команд кожного тіку (`tick`/`cmds`); гість не симулює наперед, а програє ці тіки з тим самим seed. Команди гостя йдуть хосту (`cmd`), хост ставить їм `p: 1`.

**Протокол**: `hello {nick, v}` → хост `start {seed, opts, v}`; `resync {seed, opts, log, tick, v}` при перепідключенні (журнал непорожніх команд); `cursor`, `ping` (heartbeat 1 с, таймаут 5 с), `lobby` (хост пішов у меню).

**Детермінізм** (`src/sim`):
- лише `rand(s)` з `rng.js`; ніяких `Math.random`, `Date.now`, `performance.now`
- стабільний порядок: масиви, сортування з tie-break по `id`; `Set` тільки для перевірки членства
- **будь-яка зміна sim/data → збільшити `VERSION`**, інакше перевірка версії не захистить від різного коду
- рендер (`render.js`, `critters.js`) може бути недетермінованим — він не впливає на стан

**Гравці**: `state.players[p]` — своє золото, моди талантів, кулдауни, драфти; вежі мають `owner`, чужі не можна продати/покращити/перемістити. Золото — тому, хто добив.

**Чекліст перед мерджем**:
- [ ] `tests/sim.html`: детермінізм + кооп-тести → ALL PASSED
- [ ] `tests/render.html` → ALL PASSED (помилка в рендері = зависання гри)
- [ ] `VERSION` збільшено
- [ ] нова команда валідується в `applyCmd` (власник, гроші, кулдаун) і має `p`
- [ ] вихід/перепідключення: гість → лобі, хост грає далі й робить resync
