# Pixel Tower Defense (робоча назва: td.local)

Браузерна tower defense у піксель-арт стилі. Режими: **соло**, **кооп онлайн** (2 гравці, одна карта), **versus онлайн** (кожен захищає свою базу і відправляє хвилі суперникові).

## Принципи «не скучно»
1. Рішення кожні 5–10 секунд — без довгого очікування хвиль (кнопка «виклик хвилі раніше» дає бонус).
2. Активні здібності гравця (не лише пасивні вежі).
3. Синергії між вежами (комбо-ефекти: мокрий+електрика, вогонь+масло).
4. Варіативність забігу: випадкові модифікатори/драфт карток між хвилями (roguelite).
5. Читабельність: кожен ефект має чіткий піксельний фідбек (hit flash, screen shake, числа шкоди).
6. Сесія 10–20 хв.

## Стек
- Чистий JavaScript (ES-модулі) + Canvas 2D, **без збірки і без npm** (Node.js на машині не встановлено).
- Запуск: OSPanel роздає папку — **http://td.local** (через file:// ES-модулі не працюють).
- Роздільність 480x270, масштаб під вікно з кроком 0.5, `image-rendering: pixelated`. Графіка — кодом з палітри Sweetie 16, звук — WebAudio-синтез.
- Детермінована симуляція: тік 20 Гц, seeded RNG у `state.rngState`.
- Кооп онлайн: WebRTC peer-to-peer через PeerJS (публічний signaling-сервер, свого бекенду немає). Хост веде годинник і розсилає команди кожного тіку (lockstep), гість програє ті самі тіки з тим самим seed. Versus — наступний етап.

## Структура
```
index.html, style.css
src/sim/data.js    # увесь баланс: вежі, вороги, картки, конфіг
src/sim/sim.js     # симуляція: createGame, step(state, cmds), canPlace, towerStats...
src/sim/rng.js     # seeded RNG
src/render.js      # Canvas-рендер + juice (частинки, числа шкоди, тряска)
src/sprites.js     # піксель-арт кодом, бітмап-шрифт цифр
src/audio.js       # 8-біт звуки
src/main.js        # меню/лобі, цикл (solo/host/guest), інпут, меню вежі на карті
src/net.js         # PeerJS-кооп (кімната за 5-символьним кодом)
src/meta.js        # кристали, магазин, складності, рекорди (localStorage)
tests/sim.html     # тести детермінізму + баланс-бот
docs/              # ідеї, рішення
```

## Ціль і реіграбельність
- Перемога: вистояти 20 хвиль (фінальний бос — Король слизу).
- Після кожної гри — кристали → постійні покращення й відкриття веж; перемога відкриває наступну складність.
- Кожна вежа на рівні 3 еволюціонує в 1 з 2 спеціалізацій (`BRANCHES` у data.js).
- Інтерактив на карті: бочки (вибух раз на хвилю), дерева/каміння (розчистка, скарби), монети (зібрати мишкою), гоблін-злодій.
- `?demo` у URL — одразу старт з вежами (для скріншотів).

## Правила коду
- Симуляція (`src/sim`) не знає про DOM/рендер, без `Math.random`/`Date.now`. Клієнт лише шле команди (`place`, `upgrade`, `sell`, `nextWave`, `meteor`, `pick`) і малює стан + події `state.events`.
- Баланс (вежі, вороги, хвилі) — у даних, не в коді.
- Кожна нова механіка — з перевіркою в `tests/sim.html`.
- Тести headless: `chrome --headless=new --virtual-time-budget=60000 --dump-dom http://td.local/tests/sim.html`

## Команда агентів (.claude/agents)
- `innovator` — генерує ідеї механік → `docs/ideas.md`
- `critic` — критично оцінює ідеї/архітектуру/баланс
- `developer` — реалізує
- `tester` — пише й запускає тести, шукає баги та десинхрони

Типовий цикл: innovator → critic → developer → tester (скіл `/new-feature` проводить через нього).

## Деплой
- Push у `main` → GitHub Actions (`.github/workflows/deploy.yml`) вивантажує гру по FTP у `/towerdefense.infinityfree.io/htdocs/` (лише змінені файли; `.claude`, `docs`, `tests`, `CLAUDE.md` не вивантажуються).
- Секрети репозиторію: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`.
